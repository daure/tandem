# Tandem v0.1.21 — local state and Slack correlation

## Capabilities

1. `tandem serve-state` publishes instance and OpenCode session state over a private Unix socket with the TUI closed.
2. `tandem watch --json` prints snapshots and full-object changes as NDJSON. `tandem state-socket` prints the socket path.
3. `--origin` on instance creation, fresh-session creation, and session prompting persists opaque correlation tags in each session's `origins` array.
4. `new-instance --opencode --json` returns exact session/server identity and an input receipt, including for a blank conversation. Its receipt shape matches `new-instance-session --json`.
5. Session listings and events expose model, variant, agent, context token usage, and context limit alongside activity and attachment.

Existing CLI JSON field names remain available. CLI commands and origin persistence work without a state server.

## Setup

Use the same `TANDEM_HOME`, `TANDEM_NAMESPACE`, and runtime-directory environment for the server and consumer. Install the current companion, then restart open OpenCode clients:

```sh
tandem opencode-setup
tandem serve-state
```

Run the consumer separately:

```sh
tandem state-socket
tandem watch --json
```

The server is a foreground process; the integration must manage its lifetime. Observation requires enabled OpenCode integration. The stream observes existing servers and clients; it does not launch them, submit input, or run event rules. Origin-aware launches and JSON creation receipts require the current companion. OpenCode launches require the existing Zellij setup.

## Correlating Slack messages

Example tag convention: `slack:<workspace>:<channel>:<message-ts>`. Tandem treats the tag as opaque; Slack Enricher owns its format and deduplication.

```sh
tandem new-instance slack-review -t website \
  --opencode 'Inspect this request' \
  --origin 'slack:T123:C456:1729000000.000001' --json

tandem new-instance-session slack-review 'Investigate another request' \
  --origin 'slack:T123:C456:1729000001.000002' --json

tandem prompt-session ses_example 'Follow up on this request' \
  --origin 'slack:T123:C456:1729000002.000003' --when-busy queue --json
```

Spawn commands with argument arrays rather than interpolating Slack text into shell commands. `new-instance --origin` requires `--opencode`. Omit its optional prompt to create a blank conversation.

Origins contain at most 512 Unicode scalar values. Empty strings, whitespace, and embedded newlines are preserved. The array is deduplicated in first-associated order. A session can carry several message tags. Origins persist independently of replay pruning and server restarts; confirmed Tandem session deletion removes their associations.

Creation binds the initial origin before the first session publication. A private identity handoff permits recovery after caller loss without resending input. If native creation loses its identity, creation remains uncertain and unbound sessions in that directory remain quarantined. Tandem does not infer identity from titles, timestamps, panes, or list differences. Confirmed preflight refusal releases the gate.

Follow-up prompting associates an origin before attempting delivery. A tag is neither proof of input delivery nor an idempotency key. Repeating a tagged command can create another session or submit input again.

## Receipt and failure handling

Example successful prompted-session receipt:

```json
{"session_id":"ses_example","server":"http://127.0.0.1:4199","pane":{"session":"main","id":100,"tab_id":9,"tab_name":"Review"},"prompt_outcome":"submitted","error":null}
```

| `prompt_outcome` | Meaning |
|---|---|
| `submitted` | OpenCode accepted the input; model execution or completion is not certified. |
| `queued` | OpenCode accepted durable queued input. |
| `not_submitted` | Input was not sent; this is also the successful outcome for an error-free blank-session launch. |
| `uncertain` | Delivery is unknown; inspect before retrying. |

Always capture stdout, stderr, and the exit status separately. Parse an available JSON receipt even on nonzero exit. Provisioning can fail after accepted input, and navigation or correlation-persistence errors can coexist with known identity and accepted input. Such errors produce nonzero exit without discarding the receipt. Session/server fields may be null when identity is unknown.

Never resend because a command failed, a reply was lost, or a client disconnected. Retain known identity and delivery outcome, then reconcile. `prompt-session` defaults to queue; interrupt stops current execution before steering input, while abort refuses active work or pending forms/permissions.

## State consumer contract

Each line has `type`, `version: 1`, `at` in Unix seconds, an opaque `cursor`, and `data`. Additional fields and unknown event types must be tolerated.

| Type | Data and handling |
|---|---|
| `snapshot` | Replace the complete cache using `data.instances.instances` and `data.sessions.sessions`; the enclosing objects contain listing metadata. |
| `instance.changed` | Upsert the full instance by case-normalized name. |
| `instance.removed` | Remove the instance using its last published object. |
| `session.created`, `session.changed` | Upsert the full session by `(server, session_id)`; associate every entry in `origins`. |
| `session.removed` | Remove the session from the current projection using its last published object. |
| `state.changed` | Replace listing metadata under `instances` and `sessions`; this event contains no entity arrays. |
| `replay.complete` | `data` is null; the cursor marks the replay boundary. |

Sessions include `session_id`, `server`, `instance`, `directory`, `title`, `activity`, `attached`, `panes`, `stale`, `availability`, `origins`, `model`, `variant`, `agent`, `context_tokens`, and `context_limit`. Optional metadata can be null. Activity is `busy`, `awaiting_answer`, `idle`, or `unknown`; availability is `observed`, `unverified`, or `workspace_missing`.

A snapshot is the last committed publication, not simultaneous fresh verification of every dependency. Pending OpenCode baselines retain known sessions as stale/unknown. Failed Docker observation retains known container-backed instances with stale runtime state and an inventory error. Successful observation reconciles current presence.

`removed` means an object left the projection, not proof of external deletion. Idle or awaiting-answer activity does not prove the Slack task completed. Pane IDs are transient observations, not durable session identity. No message bodies, task input, credentials, or token deltas are broadcast.

## Reconnect and bounds

For replay, keep the materialized cache and cursor together. On connection, send `{"since":"<saved-cursor>"}` plus a newline within 100 ms, or use:

```sh
tandem watch --json --since '<saved-cursor>'
```

Replay emits recorded events strictly after the saved cursor, then `replay.complete` and live events. Persist applied cache updates and their cursor atomically, including cursor advancement past unknown events. If the cache is missing, request a fresh snapshot instead.

Invalid, foreign, future, or expired cursors and backfills above 2 MiB receive a replacement snapshot with `reset: true`. Malformed subscription JSON or requests above 4096 bytes disconnect. Cursors survive server restarts. Replay covers recorded publications, not unobserved external history; an external session created and deleted during observer downtime can remain unseen.

The journal retains at most 4096 events and 32 MiB per namespace. Frames and snapshots are limited to 16 MiB. At most 16 subscribers connect; independent bounded readers isolate slow clients. Writes time out after five seconds. Journal overrun, write failure, or server shutdown disconnects the consumer. `watch` exits on disconnect; the integration must reconnect with backoff and its saved cursor or request a fresh snapshot.

The socket and its directory are private (`0600` and `0700`), and both ends verify peer UID. The stream is local Unix NDJSON, not HTTP/SSE. Subscriber count does not increase external collection: OpenCode observation is shared, and background Docker inspection uses a revision-invalidated ten-second cache. Explicit CLI inspection and manual refresh remain fresh.

## Slack Enricher implementation checklist

1. Run one managed state server for the matching Tandem home and namespace.
2. Capture creation receipts and persist `(server, session_id)` alongside the Slack tag, even when the command exits nonzero.
3. Maintain the full state cache and cursor atomically; derive Slack views from the cache and `origins`.
4. Treat unknown/stale state and partial observation errors as uncertainty, not task failure or completion.
5. Reconnect with bounded backoff; replace the cache on every snapshot and tolerate unknown events.
6. Keep Slack-side command deduplication separate from origin correlation. Reconcile uncertain input instead of automatically resending it.
